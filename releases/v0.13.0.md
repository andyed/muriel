# muriel v0.13.0 — the 8:1 floor turns outward

*Released 2026-06-27.*

v0.12.0 hardened muriel's universal 8:1 contrast floor *inward* — every channel, every generated artifact, audited against the same line. This release is that same floor reaching **outward** and, for the first time, gaining **nuance**. Three moves carry the throughline:

1. **It re-gates an external corpus.** The vendored `ui-ux-pro-max` colour sets target WCAG 3:1/AA. `muriel.uipromax` doesn't trust them — it measures every set against the 8:1 floor via `muriel.contrast`.
2. **It gets code-aware.** `muriel.devibe` scans for the visual signatures of AI-default design, but masks `<pre>`/`<code>`/comment content so a page that *documents* those tells (muriel's own docs) isn't flagged for naming them.
3. **It gains its first principled exception.** `muriel.contrast` now exempts logotypes/wordmarks per WCAG 1.4.3 — a brand glyph is a recognizable *shape*, not running text, and treating it as text was an unwarranted obstacle. A hard rule with one well-grounded carve is stronger than "no exceptions."

Plus a DTCG token importer, the motion duration-binary + easing/scale axes, HTML contrast auditing, `aiism` per-rule suppression, composition rules for `channels/polish.md`, and a Mermaid zoom/pan/expand shell for `channels/diagrams.md`.

---

## Headline 1 — `muriel.uipromax`: an external corpus, re-gated to 8:1

`muriel.uipromax` vendors the `ui-ux-pro-max` skill's seven CSV reference tables verbatim under MIT — product-type colour sets, font pairings, UI-reasoning rules, UX guidelines, design styles, a chart taxonomy, and an icon index — and wraps them in an accessor layer that re-measures every colour set against muriel's universal 8:1 floor.

The point is the posture, not the data. The corpus is unchanged; **muriel adds no colours**. What muriel adds is the gate: the source palettes target WCAG 3:1/AA, so each is run through `muriel.contrast` and surfaced with its real ratio against the 8:1 line. `palettes.uipromax_brand_palettes` and `critique.uipromax_anti_patterns` expose it to the rest of muriel; `muriel uipromax` browses and audits it from the CLI.

- Source: [nextlevelbuilder/ui-ux-pro-max-skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)
- Via: [All-The-Vibes/ATV-Design](https://github.com/All-The-Vibes/ATV-Design) (`skills/ui-ux-pro-max/`)
- Both upstreams MIT; attribution wired into `pyproject` and [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md).

This is the mining stance from earlier releases applied to a whole corpus: take the data, attribute the lineage, add the constraint muriel exists to enforce.

## Headline 2 — `muriel.devibe`: code-aware

`muriel.devibe` scans for the visual signatures of AI-default design — the tells that make someone glance at an interface and think *an AI made this*. The v0.13.0 refinement is that it's now **code-aware**: it masks the content of `<pre>`, `<code>`, and HTML comments before scanning.

The bug that forced this: muriel's own MkDocs documentation *names* the AI-design tells in order to teach them, and a naïve scanner flagged the docs for containing the very strings they document. The Material theme there is already deliberately black/cyan/system-font chrome — the "STRONG AI-default look" verdict was a false positive on teaching content, never theme chrome. Masking code/comment content fixes it: documenting a tell is not committing it.

devibe landed early as commit `6480774` on `main` so the docs build wasn't blocked waiting on the rest of this release.

## Headline 3 — logotype exemption: the floor gains a nuance

`muriel.contrast` now exempts logotypes from the 8:1 text rule, per [WCAG 1.4.3](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html) ("Text that is part of a logo or brand name has no contrast requirement"). A `_LOGOTYPE_HINTS` classifier tier — `.logo`, `.wordmark`, `.logotype`, `.lettermark`, `.brandmark`, `.monogram` — classifies as decorative (`SKIP`, exempt).

Two non-obvious details:

- **It's checked *before* the text hints.** `wordmark`, `lettermark`, and `brandmark` all contain the substring `mark`, which is a *text* hint (the `<mark>` highlight element). Checking the logotype tier first means a wordmark is exempt while a bare `<mark>` highlight stays text — the exemption can't leak onto real readable content.
- **It mirrors a softened global rule.** muriel's governing instruction moved from "8:1 on ALL text, no exceptions" to "8:1 on **readable** text" — anything parsed for meaning (UI, body, labels, captions, data, code) stays at the hard floor; logotypes and decorative display lettering, where the glyph is a recognizable shape rather than running text, are exempt and *flagged* rather than *blocked*. The change came from a real obstacle: a single brand letter in a logomark was failed as if it were body copy.

A hard rule with one well-grounded exception beats an absolute one that over-fires.

## Also in this release

- **`import-tokens` — DTCG → `brand.toml`.** Converts a [Design Tokens Community Group](https://tr.designtokens.org/) `tokens.json` into a muriel `brand.toml`, so a design team's existing token export drops straight into muriel's two-tier text-safe/decorative schema without hand-translation.
- **`muriel.motion` duration binary + axes.** A duration *binary* — utility motion ≤ 100 ms, cinematic ≥ 1500 ms, nothing in between — plus easing-by-direction (`easing_for("enter"|"exit"|"move")`), an entrance-scale floor, and property/scale validation. Paraphrased from [All-The-Vibes/ATV-Design](https://github.com/All-The-Vibes/ATV-Design)'s `emil-design-eng-inspired` (MIT, itself a clean-room paraphrase of [emilkowalski/skill](https://github.com/emilkowalski/skill)); muriel deliberately keeps its own duration binary over the source's 100–500 ms bands.
- **`muriel.contrast` HTML audit.** `audit_html()` extends the auditor from SVG to HTML — parses `<style>` blocks (skipping `@media`/`@keyframes`/`@supports`), resolves `var(--name)` chains, walks inline `style="…"` colours with per-colour dedup, auto-detects `body { background }`, and adds a four-tier status (PASS / WARN / FAIL / SKIP). Fixes a silent-PASS bug on HTML files and on SVG `<text fill="…">` attributes.
- **`muriel.aiism` per-rule suppression.** Suppress individual rules and keep a "do not chase" list of candidates already evaluated and cleared, so re-runs don't re-litigate settled calls.
- **`channels/polish.md` composition rules (23–27).** A second altitude above the tactile rules 1–22 — one focal point per view, type-scale-as-ratio (1.2 / 1.25 / 1.333), 60/30/10 colour distribution, a numbered whisper-quiet surface-elevation system, and the swap/squint/signature test battery. Paraphrased from [Dammyjay93/interface-design](https://github.com/Dammyjay93/interface-design) (MIT) **with its low-opacity/muted-colour hierarchy lever removed** — that lever demotes text by dropping it below contrast, which collides with the 8:1 floor; the same hierarchy is rebuilt on weight + size + space, every tier ≥ 8:1. (The source's polish/motion section was *not* imported — muriel rules 1–22 already cover it, more precisely.)
- **`channels/diagrams.md` Mermaid zoom/pan/expand shell.** A runtime `.diagram-shell` viewport for Mermaid rendered client-side: zoom (+ / − / fit / 1:1), drag-pan, pinch, and expand-to-full-window, so a large flowchart isn't an unreadable thumbnail. Theme-driven by `--mg-*` brand tokens; chrome clears 8:1; motion-safe by construction (pan/zoom are direct manipulation, only button hover animates, disabled under `prefers-reduced-motion`). Closes a gap surfaced against [nicobailon/visual-explainer](https://github.com/nicobailon/visual-explainer)'s `diagram-shell` pattern.
- **`fix(spatial)`** — CSS3D cards depth-sort by camera distance, fixing draw-order overlap in the spatial exemplars and the gallery.

## Migration

- **No breaking changes.** Every addition is additive.
- **No channel-count change** — `polish` and `diagrams` are existing channels; the additions extend them.
- **Contrast behaviour change (intentional):** selectors that name a logotype (`.logo`/`.wordmark`/etc.) now report `SKIP` instead of `FAIL`/`WARN`. If you were relying on a logo selector failing the audit, rename it or treat the SKIP as the new correct verdict.
- `pyproject` version 0.12.0 → 0.13.0.
